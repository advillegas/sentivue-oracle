# Hardened Kilo — the in-repo fork posture

SentiVue Oracle ships Kilo Code as a **hardened, self-contained fork**: the
pinned upstream binary (`@kilocode/cli` 7.4.5, an OpenCode fork) unmodified on
disk, wrapped by a hardening layer that removes every path by which Kilo can
talk to anything other than the local model gateway.

Upstream Kilo is cloud-first (account, gateway, 500+ hosted models, session
sharing, product analytics). We use **none** of that: the only provider is
`llama-swap` on `127.0.0.1:9099`. This fork exists to make that non-negotiable.

## Why the binary is not recompiled

`kilo.exe` / `kilo` is a ~140 MB compiled Bun single-file executable. Rebuilding
it from source (`Kilo-Org/kilocode`) offline is not tractable inside this
appliance, and a patched binary would be an unpinnable, unverifiable artifact.
Instead we **contain** the stock binary with three independent layers, so no
single bypass re-enables a call-home path:

1. **Config** — `state/generated/kilo/kilo.jsonc` (generated by `sync-models`
   and selected explicitly with `KILO_CONFIG`) pins
   the sole provider to local llama-swap, `share: "disabled"`, telemetry off,
   `permission.webfetch: "deny"`, and carries **no remote `$schema`** (so the
   editor never fetches `app.kilo.ai/config.json`).
2. **Environment** — `hardened-env.{sh,ps1}` (sourced by the launchers, so it
   also covers conductor missions and every agent tab) sets the documented Kilo
   kill-switches: telemetry/OTEL off, sharing + session ingest off, remote relay
   + websockets + embedded web UI off, autoupdate off, remote model fetch off,
   LSP/plugin/skill downloads off, Exa/websearch off, blank gateway credentials.
3. **Network (the guarantee)** — `bootstrap/harden-egress.{ps1,sh}` applies an
   OS-level **default-deny egress** to the Kilo process (and every other
   appliance process). Loopback still works, so local models are reachable; the
   public internet is not. Even if a knob is ignored or an upgrade adds a new
   endpoint, the packets do not leave the machine.

Layers 1–2 are defense-in-depth and best-effort (they depend on the vendor
honoring documented flags). **Layer 3 is the iron-clad guarantee** and does not
trust the binary at all.

## What is disabled (mapped to the request)

| Feature | How it is disabled |
|---|---|
| Kilo Gateway | no gateway provider in config; blank `KILO_API_KEY`; `api.kilo.ai` egress-blocked |
| Login / account | never authenticated; blank `KILO_ORG_ID`; auth hosts egress-blocked |
| Cloud sharing | `share:"disabled"`, `KILO_DISABLE_SHARE=1`, `KILO_AUTO_SHARE=0`, `KILO_DISABLE_SESSION_INGEST=1`; `ingest.kilosessions.ai` + `*.kiloapps.io` blocked |
| Remote control / relay | `KILO_REMOTE=0`, `KILO_EXPERIMENTAL_WEBSOCKETS=0`, `KILO_DISABLE_EMBEDDED_WEB_UI=1`; relay hosts blocked |
| Feedback submission | no feedback path invoked; feedback hosts blocked |
| Sentry / PostHog / OpenTelemetry | `KILO_TELEMETRY_LEVEL=off`, `OTEL_SDK_DISABLED=true`, exporters `none`; `sentry.io` + `us.i.posthog.com` blocked |
| Update checks | `KILO_DISABLE_AUTOUPDATE=1`, `KILO_ALWAYS_NOTIFY_UPDATE=0`; release/chocolatey hosts blocked |
| Marketplace calls | no marketplace surface; hosts blocked |
| Remote model discovery | `KILO_DISABLE_MODELS_FETCH=1`; `models.dev` blocked |
| External autocomplete | provider is local-only; `KILO_ENABLE_EXA=0`, `KILO_WEBSEARCH_PROVIDER=none`, `KILO_DISABLE_DEFAULT_PLUGINS=1` |
| Remote config schemas | remote `$schema` removed from generated `kilo.jsonc` |
| Endpoint fallback at build | `KILO_DISABLE_MODELS_FETCH=1`, `KILO_DISABLE_LSP_DOWNLOAD=1`, `KILO_DISABLE_EXTERNAL_SKILLS=1`; all fallback hosts blocked |

## Re-verifying after a Kilo version bump

The env knobs and `call-home-hosts.txt` were derived by scanning the pinned
binary. When `KILO_CLI_NPM_VERSION` changes in `VERSIONS.lock`:

1. Re-scan: `node bootstrap/scan-binary.mjs <path-to-kilo(.exe)> > engines/kilo/call-home-hosts.new`
2. Diff against `call-home-hosts.txt`; add any new hosts.
3. `oracle audit` (security sweep) and `oracle verify-egress` must stay green.

The egress default-deny needs no re-derivation — it blocks everything not on the
loopback by construction, so new endpoints are covered automatically.
